Track filter — one row per question, the answer is a word

The current flyout is a settings dialog in a popover: an icon tile, a subtitle, three section captions, two three-way segmented controls whose first segment says All, a check box inside a bordered card, two expanders hiding the ranges, and a status footer. The redesign is the Zune grammar inside a Fluent flyout: every facet is one row whose options are words, the chosen word is bright with the Home tab's underline, binary facets are plain check boxes, the search scope moves into the search box where it belongs, and the only chrome is a title, an active count and Clear.

What is wrong with the flyout today

  1. It is a dialog wearing a popover. A 40-DIP icon tile, a two-line header ("Filter tracks / All tracks"), three section captions and a status footer for six questions. → a 16-DIP title, the count, Clear. Nothing else is chrome.
  2. "All · Hide · Only" is unreadable. For "Explicit content", All reads as "all explicit". The three words answer different questions. → Show · Hide · Only: three verbs about the same thing, and the label is the noun ("Explicit").
  3. Segmented plates and bordered cards inside a flyout. Two rounded segmented controls, a check box wrapped in its own card, expanders with chevrons: four container styles on one surface. → words on the flyout ground; the chosen word carries the same 2-DIP underline the Home tabs use. One vocabulary.
  4. The ranges hide. Duration and Tempo are expanders showing "Any duration"; you open one to learn the choices. → every option is visible; a facet is one row you scan, not a drawer you open.
  5. "Search in" is not a filter. It scopes the search box, yet it is the first thing in the filter panel. → it moves into the search box as a scope chip (WinUI AutoSuggestBox with a scope), and the filter panel is only about what the list shows.
  6. The footer states the obvious. "No filters applied" next to a disabled Clear button. → the count in the header ("2 active · 133 of 148 songs") says what the filter is doing; Clear sits beside it and is dimmed at zero.

The model does not change: TrackFilterState's facets map one to one; only the vocabulary and the chrome do. "All" becomes "Show" on the traits, "Duration" becomes "Length" (the column is already called that), and the tempo bands get the listener words the enum's own doc comment uses.

Why this is the Fluent/Zune answer

  • Zune: navigation and choice as typography. Metro grew out of Zune's habit of using words as controls, the active one bright and the rest quiet, with no boxes around them. A facet row of words is that idiom applied to a filter.
  • Fluent: one surface, one vocabulary. A WinUI Flyout carries content on its own acrylic; it does not nest cards, segmented plates and expanders inside itself. Check boxes and radio groups are the native primitives for exactly these questions.
  • Show everything, decide in place. WinUI's guidance for a small option set is to show it (RadioButtons), not to hide it behind a ComboBox or an expander; the sets here are three to five words long.
  • The count is the feedback. "2 active · 133 of 148 songs" tells the user what the filter did before they close the flyout; a "No filters applied" footer only told them what it did not do.
  • Scope belongs to the search box. "Search in" answers "where does my text match", which is a property of the text field, not of the list's filter; the AutoSuggestBox-with-scope shape is where every Microsoft app puts it.
