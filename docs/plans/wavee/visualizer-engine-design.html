Visualizer engine design

This document gives the engine design for the Wavee stage visualizers. It tells how a frame moves through the engine. It tells which new parts the engine must have, and how each part operates. It does not give the app design.

In the figures, this colour shows a new engine part. All other parts exist today.

1. Scope

The Wavee stage shows a full-screen visualizer face. There are 19 faces. Each face reads audio data and draws shapes on each frame.

Eleven faces use only the primitives that the engine has today. Three faces are possible today, but they look bad or use too much UI-thread time. Five faces cannot operate without new engine parts: Scope, Warp, Magneto, Drift and Flow.

This design adds seven features. Each feature uses an engine shape that exists: an Element record, a bound Prop.Of channel, a scene side table, a POD draw operation or a composite item. The design does not add a custom shader hook.

All statements about existing code come from the engine plan. That plan gives a file and line reference for each statement.

2. The frame path

Audio data and drawing data use different threads. The figure shows the path from the audio output to the GPU.

Thread rules

  • The audio RT thread only writes the mono ring. The design does not add work on this thread.
  • The control thread analyses the latency-aligned 2048-sample window. It publishes results through a double buffer.
  • The UI thread folds the published data into the face model. It writes the values into FloatSignals. Bound props write scene columns.
  • The UI thread records a POD draw list. The render thread submits the last complete draw list.
  • Phases 6 to 13 of a frame must not allocate managed memory. All new features obey this rule.

3. Retained tiles and skip-submit

The primary window uses a retained tiled composite. The engine rasters slices into tiles of 1024 × 512 pixels. Then it composites all tiles in one pass.

The engine does not submit a frame that is equal to the last frame. Three conditions must all be true for a skip. The figure shows these conditions.

A full-screen face is one RepaintBoundary slice. When its bytes change, the engine rasters all tiles under it again. At 1920 × 1080 this is 6 tiles. At 3440 × 1440 this is 12 tiles. This cost is the floor for each animated face.

Rule: a face must not paint the top and bottom tile rows if it does not need them. Then the engine rasters fewer tiles.

F1 · Waveform tap, spectral flux and onset

Scope and Flow need the sound wave itself, not only the frequency bands. Faces also need a beat signal when a track has no Spotify beat grid.

Mechanism
After analyzer.Analyze, the control thread copies the centre 1024 samples of the 2048-sample window. It publishes them in a double buffer, next to the bands.
Flux
Flux is the mean of the positive band changes between two frames: Σ max(0, band[i] − prev[i]) / 48. A ring of 96 values (≈1.5 s) gives the mean and the deviation.
Onset
An onset occurs when flux is more than mean + 1.5σ and 100 ms or more have elapsed since the last onset.
API
IAudioEffects.CopyWaveform(Span<float>, out WaveformInfo). SpectrumInfo gets Flux, OnsetSequence and OnsetStrength.
Limits
Mono only. The RT tap downmixes, and no face needs stereo. The design does not add a UI presentation-latency term.
Cost
One copy of 4 KB and a few additions per hop. No allocation. No new thread.

F2 · GradientMix

Gradients are static today. A palette change on the beat must not rebuild each face.

Mechanism
A node has a static GradientTo and a bound Prop<float> GradientMix. The recorder blends the stops on stack memory at record time. It uses the LerpStops function that hover gradients use today.
API
BoxEl.GradientTo, BoxEl.GradientMix; the same two members on SeriesEl. GradientTo must have the same stop count as Gradient.
Why not a bound GradientSpec
A thunk that returns a GradientSpec makes a new object and a new stop array on each fire. That breaks the zero-allocation rule.
Cost
No new draw operation and no backend change. A palette rotation causes one reconcile of the face root at the end of the 900 ms blend.

F3 · Series lane v2

Polar
SeriesShape.Polar: each sample is a radius fraction around the box centre. The angle is 2π·i/(N−1). Sample 0 repeats to close the loop. Each chunk gets Prev and Next samples for a correct tangent.
Gradient axis
SeriesGradientAxis.Along puts the gradient on the sample index. Today the gradient follows the amplitude only.
Anti-aliasing
The pixel shader feathers coverage from the signed distance to the ribbon edge. The quad already extends by half the thickness, so the repaint halo covers the fringe.
Cost
The draw count does not change. A Polar series uses the full box as its bounds.

F4 · Additive paint and Screen composite

Glowing particles must add light. Today every pipeline uses premultiplied source-over. Overlaps then look muddy. The design adds two different blends, because they operate at different stages.

API
PaintBlend { SrcOver, Additive } on BoxEl, SeriesEl, SpriteFieldEl. LayerBlend { SrcOver, Screen } on a BoxEl that is a repaint boundary.
Draw op
SetBlend { byte Mode }. The D3D12 decoder breaks the current run and selects the additive PSO clone. Glyphs and paths stay source-over in v1.
Composite
CompositeItem.BlendCopy becomes an enum { Over, Copy, DestOut, Screen }.

F5 · SpriteFieldEl

Warp has 220 streaks. With one node for each streak, the UI thread fires 440 binds on each frame. F5 puts all sprites in one node.

API
SpriteFieldEl { Prop<SpriteInstances> Instances; SpriteKernel Kernel; PaintBlend Blend; float Opacity; }, ElementTypeId 19, VisualKind.Sprites 11.
Limits
More than 1024 sprites: the engine drops the extra sprites and counts them. More than 4096 instances in a frame: the engine drops and counts them in Diag.
Bounds
The recorder computes the chunk rectangle on the UI thread. It includes rotation and the soft reach. RepaintCull.SpriteHalo adds the AA pad.

F6 · Feedback slice

Drift and Flow draw the last frame again, a little zoomed, turned and faded. Then they draw new content on top. This needs a surface that persists from frame to frame.

API
BoxEl.Feedback : FeedbackSpec(Decay, RasterScale = 0.5, FadeTo, Fresh), Prop<Affine2D> FeedbackTransform, Prop<float> FeedbackDecay. A feedback node is a repaint boundary with no tiles.
Surfaces
The render thread leases two surfaces from SurfacePool and pins them. The idle trim does not touch pinned surfaces. The engine releases them through the fenced retire queue.
Frame rate
The engine applies Decay per advance. The app must scale Decay by dt / 16.7 ms. Then the trail looks the same at 60 Hz and at 144 Hz.
Format
BGRA8 only. The dither and FadeTo stop 8-bit residue. F16 is the fallback if dark trails show banding.
Resize, DPI
The engine releases a pair with a changed size and leases a new empty pair. The trail restarts for one frame.
Device lost
The engine drops the table with the other surfaces and rebuilds it empty.

VRAM for one ping-pong pair = 2 × W × H × 4 / down². A new budget term TileBudget.FeedbackBytes holds it. If a request is too large, the engine forces the next scale down and counts feedback.forcedDown.

F7 · Governor-paceable frame clock

The adaptive GPU governor paces continuous motion to 30 fps when GPU time is too high. Today it never paces a FrameClockPoller. Thus a GPU-heavy visualizer always runs at the panel rate.

Mechanism
FrameClock.Subscribe(tick, paceable: true) sets a new wake bit, FrameClockPaceable. This bit is not in GpuGovernorWake.NeverPace. It is in the PowerCap set.
Users
The visualizer clock subscribes as paceable. Lyrics and scroll-linked pollers do not.
Signal
A face reads AppHost.GpuGovernorEngaged to use fewer sprites. The design adds no new signal.

7. Performance budget

These values are estimates. The base is one measured value: an Adreno X1-85 iGPU rasters one tile, with the composite, in about 0.3 ms. A full-screen face re-rasters all its tiles on each tick. Thus the floor is about 2 ms at 1080p and 4 ms at 3440 × 1440 on an iGPU.

Target: each face uses 6 ms or less on an iGPU at 3440 × 1440, and 3 ms or less at 1080p. The governor engages at 10 ms.

  • With F5, the UI thread does one copy of 32 KB or less and one slice record per tick.

  • VRAM at 3440 × 1440: 24 MiB of face tiles (budget 99 MiB) and 9.9 MB for one feedback pair.

8. Tests and gates

Engine.Tests (headless, no device)

  • DrawSpritesCmdTests, SetBlendCmdTests: no managed references, size 1024 B or less, correct body size, correct bounds.
  • SpriteFieldBindTests: copy, cap at 1024 with a drop count, version gate, zero allocation after warm-up.
  • SeriesPolarTests, SeriesGradientAxisTests, GradientMixTests.
  • SpectrumFluxTests, WaveformPublishTests: no onset on a steady tone; one onset on a step; samples align with the band sequence.
  • FeedbackClockTests: no skip while feedbackLive; correct settle count; the host parks after settle.
  • GovernorPaceableClockTests: the governor paces a paceable poller only; PowerCap caps both.

Pixel checks (GPU)

  • Additive sprites on a mid-grey plate equal plate + Σ, within 1/255.
  • A Screen item equals the CPU formula.
  • After N advances with no warp, one disc equals (1 − decay)^N, within the dither.

10. Rejected features

CandidateDecisionReason
Custom shader hookRejectedThe headless device has no pixels, so a gate cannot test it. An opaque kernel cannot declare its raster halo, so retained tiles can show cut shapes. A PSO per app shader breaks the deduplicated pipeline set. Detached windows and a Metal port need each kernel twice.
New glow primitiveRejectedThe in-flight RasterScale repaint boundary is the glow route. F6 adds blur at low resolution.
Bound GradientSpecRejectedIt allocates on each fire. F2 replaces it.
Stereo scopeRejectedThe RT tap downmixes. Stereo doubles the ring and changes the RT path for no face.
Per-glyph text channelsNot in v1Verse uses one TextEl for each word and GlyphWipe inside the word.
F16 feedbackNot defaultIt doubles VRAM and needs a second pool format. Dither and FadeTo are the v1 answer.

11. Open questions

  1. Feedback precision: use 8-bit with dither for v1, or add the F16 pool format now (+1.5 d)?
  2. Must the visualizer clock be governor-paceable by default? Recommendation: yes. Then a weak GPU slows the face, not the full app.
  3. Pop-out windows: accept the flat fold-downs, or add composite support for secondary targets later?
  4. Palette moments: use the Spotify 8-bar downbeat with flux as fallback, or use flux for all tracks?
